# 구조 검사기 (his-check)

앱을 고치기 **전후**로 한 번씩 돌리는 검사입니다. 앱 동작은 전혀 건드리지 않고, 코드만 읽어서
«나중에 사고로 이어지는 패턴»을 찾아 알려줍니다.

## 쓰는 법

```bash
py _check/his-check.py
```

- **«통과 — 새 코드는 깨끗합니다»** 가 나오면 커밋해도 됩니다.
- **«새로 생긴 위반 N건»** 이 나오면 그 부분만 고치면 됩니다. 기존 것까지 다 고칠 필요 없습니다.

기존 위반을 하나 정리했으면 기준선을 다시 저장합니다.

```bash
py _check/his-check.py --save
```

전체 목록을 다 보고 싶을 때:

```bash
py _check/his-check.py --all
```

## 무엇을 보나

| 규칙 | 내용 | 왜 |
|---|---|---|
| R0 | 파일 무결성 | 페이로드가 깨지면 앱이 통째로 흰 화면 |
| R1 | 학생 명단 직접 읽기 | 보관함(반 삭제된 퇴원생)·담임 스코프·접수대기 제외가 빠짐 |
| R2 | 시간표 직접 읽기 | 구형식·보강/휴강이 반영 안 돼 화면마다 시간이 다르게 보임 |
| R3 | 기기 간 합치기 누락 | 두 기기가 동시에 쓰면 한쪽이 통째로 사라짐 |
| R4 | 복제 화면 불일치 | 같은 화면이 3벌인데 한쪽만 고쳐 화면마다 다르게 보임 |
| R5 | 프레임워크 함정 | 버튼이 조용히 먹통 / 부팅 때 404 |
| R6 | 앱 밖 서버 규칙 | 앱만 고치고 알림톡 서버는 옛 규칙으로 남음 |

## 정본 함수 (이걸 쓰면 R1·R2가 자동으로 해결됩니다)

- 학생 명단 → `visibleClasses(data, user)` 또는 `_schedClasses(...)`
- 수업 시작·종료 시각 → `_classStart(c, w, date, data)` / `_classEnd(...)`

새 코드에서 `data.classes`나 `sc.days`를 직접 읽지 마세요.

## 기준선(baseline.json)

지금 남아 있는 위반 목록입니다. **코드 내용으로 식별**하기 때문에 다른 곳을 고쳐도 흔들리지 않습니다.
목록에 없던 것이 나타나면 «새로 생긴 위반»으로 잡힙니다.
